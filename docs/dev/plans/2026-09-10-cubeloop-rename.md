# CubePlex cutover to CubeLoop 0.14.1 — plan

**Goal:** Pin CubePlex on `cubeloop` 0.14.1, rewrite live imports and
CubePlex identifiers, cut Tempo over to `cubeloop.*` attributes, and
update current docs and skills. Do **not** migrate checkpointer tables.

**Architecture:** One release-shaped cutover of the Python package and
the admin trace viewer. Physical Postgres names stay `cubepi_*` at
schema version 5 — no new Alembic revision. The pin, the helper-import
retarget in historical revisions, the live import rewrite, and the Tempo
attribute rename must ship together: after `uv add` removes `cubepi`,
v1's `from cubepi.checkpointer…` breaks greenfield alembic, and 0.14.1
spans are invisible to today's `span.cubepi.*` TraceQL. Frozen
`docs/dev` snapshots and SQL inside historical Alembic revisions stay.
CubePlex does not install the `cubepi` 0.14.1 tombstone.

**Tech stack:** Python 3.13 / `uv` / cubeloop 0.14.1 (git tag `v0.14.1`
on `cubeplexai/cubeloop`) / Postgres checkpointer schema 5 / Tempo
TraceQL / FastAPI / pytest.

Spec: [2026-09-10-cubeloop-rename-design.md](../specs/2026-09-10-cubeloop-rename-design.md).

## Unit 1 — Pin cubeloop 0.14.1 + Alembic import retarget

One slice. After `uv add`, historical revisions still `import cubepi`
until this unit's Alembic edits land. Do not run `alembic upgrade` or
e2e between the pin and those edits.

**Files**

- `backend/pyproject.toml` — replace the `cubepi[…]` project dep and
  the `[tool.uv.sources]` git override with `cubeloop` pointed at
  `https://github.com/cubeplexai/cubeloop.git` rev `v0.14.1`. Description
  string drops "with cubepi".
- `backend/uv.lock` — regenerated by `uv add` / `uv lock`.
- `backend/alembic/env.py` — `from cubeloop.checkpointer.postgres.models
  import cubeloop_metadata`; `target_metadata` uses that symbol. Exclusion
  set stays on `cubepi_*` names (metadata still describes those tables).
- Historical revisions that import
  `cubepi.checkpointer.postgres.alembic_helpers` — import path becomes
  `cubeloop.checkpointer.postgres.alembic_helpers`. SQL they emit is
  unchanged (`cubepi_*`, `write_schema_version_op` still writes 5).
- `eef196f4c8f9` — leave the `cubepi.providers.catalog` ImportError
  branch.
- `backend/tests/unit/test_alembic_env.py` — assert `cubeloop_metadata`
  / `cubeloop.checkpointer.postgres`.

**Interfaces**

```
cubeloop[mcp,postgres,trace-cli,tracing,tracing-otlp] @
  git+https://github.com/cubeplexai/cubeloop.git@v0.14.1
```

No `cubepi` extra, no tombstone wheel. No `upgrade_v5_to_v6_op`.

**Core logic**

From `backend/`:

```
uv add 'cubeloop[mcp,postgres,trace-cli,tracing,tracing-otlp] @ git+https://github.com/cubeplexai/cubeloop.git@v0.14.1'
```

If `uv add` leaves a leftover `cubepi` source or project line, delete
that line and re-lock. Inspect the lock diff: cubeloop plus its direct
transitives may move; unrelated pins should not.

Then retarget `env.py` and the historical helper imports. Do not
generate a new revision. Do not inline v1 partition SQL —
`create_message_partitions_op()` still emits `cubepi_messages_pXX`.

0.13.6 (compaction trailing-synthetic fix) is included in 0.14.1. No
CubePlex code is expected for it.

**Tests**

- `uv run python -c "import cubeloop, cubeloop.agent, cubeloop.checkpointer.postgres; import cubepi"`
  — cubeloop imports, `cubepi` raises `ModuleNotFoundError`.
- `git diff backend/uv.lock` reviewed before commit.
- Unit: `test_alembic_env.py` updated.
- Worktree **dev** DB (already at v5): `alembic upgrade head` is a
  no-op; `\dt cubepi_*` still there; `SELECT version FROM
  cubepi_schema_version` → `5`.
- Greenfield: e2e test-DB bootstrap (`alembic upgrade head` on an empty
  `cubeplex_test_*` database) still replays v1→v5.

This unit will not boot the agent path by itself (application imports
still say `cubepi`). Combined with Unit 2 in one implementation PR.

## Unit 2 — Import + identifier rewrite

**Files**

Every live Python file under `backend/cubeplex/`, `backend/tests/`,
and `backend/main.py` that mentions cubepi as an import or CubePlex
symbol. Highest-churn:

- `cubeplex/streams/run_manager.py` — class/function names in the spec
  table (`CubeloopAgentRunError`, `_run_cubeloop_path`,
  `cubeloop_dict_to_agent_event`, …).
- `cubeplex/mcp/cubepi_runtime.py` → `cubeloop_runtime.py` (git mv) and
  every importer (`disclosure.py`, `mcp_discovery.py`, `admin_mcp.py`,
  `ws_mcp.py`, `oauth/callback.py`, tests).
- `cubeplex/agents/{graph,convert,stream,tracing,checkpointer}.py`
- `cubeplex/llm/builder.py` and the rest of `llm/`
- `cubeplex/tools/**`, `cubeplex/middleware/**`
- Tests named `test_cubepi_*.py` / `test_run_manager_cubepi_*.py` —
  git mv to `test_cubeloop_*`.

Do **not** rewrite `docs/dev/**`. Do **not** rewrite SQL strings inside
historical Alembic revisions. Do **not** rewrite live
`FROM cubepi_messages` / `cubepi_threads` / `cubepi_runs`.

**Interfaces**

Public-to-CubePlex callables after the rename (same signatures, new
names):

```python
class CubeloopAgentRunError(RuntimeError): ...
def cubeloop_dict_to_agent_event(d: dict[str, Any], timestamp: str) -> AgentEvent | None: ...
def wire_input_to_cubeloop_user_message(...) -> UserMessage: ...
def steering_message_to_cubeloop(row: SteeringMessage) -> UserMessage: ...
async def load_workspace_mcp_tools_for_cubeloop(...) -> list[AgentTool]: ...
```

Library imports: `from cubeloop import Agent, tool` and the existing
submodule paths with the root swapped (`cubeloop.providers.base`,
`cubeloop.hitl`, `cubeloop.middleware.compaction`, …). Submodule layout
did not change in 0.14.1. SQLAlchemy symbol is `cubeloop_metadata`;
`__tablename__` values stay `cubepi_*`.

**Core logic**

Mechanical, but not a blind repo-wide sed: skip `docs/dev`, skip SQL
table identifiers, skip the `eef196f4c8f9` catalog ImportError. After
the rewrite, a case-sensitive `from cubepi` / `import cubepi` grep of
`backend/cubeplex`, `backend/tests`, and `backend/alembic/env.py` is
empty except that one migration.

**Tests**

Existing unit tests keep their assertions; they just import the new
names. Update tests that `hasattr(RunManager, "_run_cubepi_path")` or
patch `cubeplex.mcp.cubepi_runtime.*`. No new behavioural tests in this
unit — behaviour is unchanged.

Run the focused unit files that import the renamed symbols
(`test_run_manager_cubeloop_dict_to_event`, `test_graph`,
`test_alembic_env`, `tests/unit/mcp/test_runtime_*`). History / fork /
delete e2e can run in this same PR — tables did not move.

## Unit 3 — Tempo cubeloop-only attribute names

**Files**

- `backend/cubeplex/services/tempo_client.py` — parser, TraceQL,
  search-hit summary: every `cubepi.` vendor key becomes `cubeloop.`.
- `backend/cubeplex/api/routes/v1/admin_traces.py` — tag allowlist and
  `_has_foreign_org_span`.
- `backend/cubeplex/api/schemas/trace.py` — comments only (`cubeloop.turn`).
- `backend/tests/unit/test_tempo_client.py`, `test_tempo_parser.py`
- `backend/tests/fixtures/tempo/` — rewrite `cubepi.*` keys in the JSON
  fixtures to `cubeloop.*`.
- `backend/tests/e2e/test_admin_traces.py` — allowlist tag names.

**Interfaces**

Parser keys (cubeloop only; no cubepi fallback):

```
cubeloop.run_id
cubeloop.metadata.{org,workspace,user,conversation}_id
cubeloop.turn / cubeloop.turn.index / .stop_reason / .tool_calls.count
cubeloop.agent.tools
cubeloop.llm.raw_request / raw_response
cubeloop.tool.is_error / execution_mode
```

`gen_ai.*` is unchanged. Span name `cubepi.turn` is no longer classified
as a turn.

TraceQL org gate (and each optional filter) stays as sibling spansets so
org_id on `invoke_agent` and `gen_ai.request.model` on a chat span can
match independently — only the vendor prefix changes:

```
{ resource.service.name="cubeplex" &&
  span.cubeloop.metadata.org_id="…" }
```

`select(...)` lists the cubeloop spellings.

Tag allowlist is `cubeloop.metadata.{workspace,user,conversation}_id`
plus `gen_ai.request.model`. `_has_foreign_org_span` reads
`cubeloop.metadata.org_id` only.

**Core logic**

String-replace the vendor prefix in the viewer. Do not dual-read, do
not dual-write. CubePlex already passes unprefixed metadata into
`tracing_context`; 0.14.1 prefixes it `cubeloop.metadata.*`. Pre-0.14
Tempo documents with `cubepi.*` keys stop matching search and fail the
org-id gate on detail (`org_id is None → 404`). That is accepted.

**Tests**

Unit, in `tests/unit/test_tempo_parser.py` / `test_tempo_client.py`
(update the existing assertions; no new dual-namespace cases):

1. Rewritten cubeloop fixtures still parse business ids, turn kind, raw
   request/response.
2. Search TraceQL for an org contains `span.cubeloop.metadata.org_id`
   and does **not** contain `span.cubepi.`.
3. Tag-values allowlist accepts the cubeloop spellings; a `cubepi.*`
   tag and a random tag still 400.
4. `_has_foreign_org_span` flags a child whose
   `cubeloop.metadata.org_id` differs.

E2E `test_admin_traces.py` keeps covering the HTTP 404-on-foreign-org
path with `cubeloop.metadata.org_id`.

## Risk register

1. **Helper imports not retargeted before alembic/e2e.** After the pin,
   v1 still `from cubepi.checkpointer…`. Mitigation: Unit 1 is one
   slice; no alembic/e2e between `uv add` and the import retarget.
2. **Tempo 0.14.1 traces invisible if Unit 3 slips.** The attribute
   rename must ship in the same PR as the pin. Pre-0.14 `cubepi.*`
   traces going dark is accepted (no dual-read).
3. **Lockfile churn.** Review `uv.lock` for unrelated bumps before
   commit.
4. **Identifier rename misses a patch string.** Tests that monkeypatch
   `cubeplex.mcp.cubepi_runtime.…` will fail loudly; grep the old module
   path after the git mv.
5. **Blind sed of `cubepi_messages`.** Table names must stay. The
   identifier rewrite skips SQL strings.

---

## Out of this plan

Matches the spec: no PyPI-instead-of-git switch, no tombstone dep, no
table rename, no frozen docs rewrite, no JSONL directory migration, no
dual-read or dual-write of OTel attrs, no new CubeLoop APIs.
