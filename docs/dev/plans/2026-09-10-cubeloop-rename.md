# CubePlex cutover to CubeLoop 0.14 — plan

**Goal:** Pin CubePlex on `cubeloop` 0.14.0, migrate checkpointer tables
v5→v6, rewrite live imports/identifiers/SQL, dual-read Tempo traces, and
update current docs and skills.

**Architecture:** One release-shaped cutover. The pin, the Alembic
rename, the import rewrite, and the Tempo dual-read must ship together:
opening 0.14 against v5 raises `CubeloopSchemaMismatch`, and 0.14 spans
are invisible to today's `span.cubepi.*` TraceQL. Frozen `docs/dev`
snapshots and the SQL inside historical Alembic revisions stay as they
are. CubePlex does not install the `cubepi` 0.14 shim.

**Tech stack:** Python 3.13 / `uv` / cubeloop 0.14.0 (git tag `v0.14.0`
on `cubeplexai/cubeloop`) / Postgres checkpointer schema 6 / Tempo
TraceQL / FastAPI / pytest.

Spec: [2026-09-10-cubeloop-rename-design.md](../specs/2026-09-10-cubeloop-rename-design.md).

## Unit 2 — Alembic env.py + v5→v6 revision

**Files**

- `backend/alembic/env.py` — `cubeloop_metadata`; exclude both
  `cubepi_*` and `cubeloop_*` parents and partition prefixes from
  autogenerate.
- `backend/alembic/versions/<auto>_cubeloop_v5_to_v6_rename.py` —
  created via `--autogenerate`, body filled with the upstream helpers.
- Historical revisions that import
  `cubepi.checkpointer.postgres.alembic_helpers` — import path only
  becomes `cubeloop.checkpointer.postgres.alembic_helpers`. SQL they
  emit stays `cubepi_*`.
- `eef196f4c8f9` — leave the `cubepi.providers.catalog` ImportError
  branch; that module never existed on cubeloop.
- `backend/tests/unit/test_alembic_env.py` — assert `cubeloop_metadata`
  / `cubeloop.checkpointer.postgres`.

**Interfaces**

```python
from cubeloop.checkpointer.postgres.alembic_helpers import (
    upgrade_v5_to_v6_op,
    write_schema_version_op,
)

def upgrade() -> None:
    op.execute(upgrade_v5_to_v6_op())
    op.execute(write_schema_version_op())  # writes 6 into cubeloop_schema_version
```

Downgrade reverses the rename (parents, 64+64 partitions, hitl_answers,
schema_version, `ix_cubeloop_*` → `ix_cubepi_*`) and writes version 5
into `cubepi_schema_version`. It must not `DROP` those tables.

`env.py` exclusion set after this unit:

- Tables: existing checkpoint leftovers plus `cubepi_hitl_answers`,
  `cubepi_messages`, `cubepi_runs`, `cubepi_schema_version`,
  `cubeloop_hitl_answers`, `cubeloop_messages`, `cubeloop_runs`,
  `cubeloop_schema_version`, `cubeloop_threads` (threads was never in
  the set because the v1 autogen created it; adding the cubeloop name
  prevents a post-rename autogen from trying to drop it as "not in
  SQLModel metadata" if reflection and metadata ever disagree).
- Prefixes: `cubepi_messages_p`, `cubepi_runs_p`, `cubeloop_messages_p`,
  `cubeloop_runs_p`.

**Core logic**

Order is load-bearing:

1. Edit `env.py` so autogen against a still-v5 DB does not propose
   `DROP cubepi_*` / `CREATE cubeloop_*`.
2. `cd backend && uv run alembic heads` — single head; capture it.
3. `uv run alembic revision --autogenerate -m "cubeloop v5 to v6 rename"`.
   Empty body is the expected outcome.
4. Hand-add the two `op.execute` calls. `down_revision` is the captured
   head.
5. Then change historical helper imports.

`write_schema_version_op()` in 0.14 already chooses cubeloop vs cubepi
version table by which one exists. Do not special-case old revisions.

**Tests**

- Unit: `test_alembic_env.py` updated.
- Verify (command, not a new test file): on the worktree **dev** DB
  (already at v5 from worktree init) run `alembic upgrade head`, then
  `\dt cubeloop_*`, `\dt cubepi_*` (data tables gone), `SELECT version
  FROM cubeloop_schema_version` → `6`.
- E2E that opens the checkpointer (`test_cubeloop_checkpointer_integration`,
  renamed in Unit 3) is the contract that `_verify_schema` accepts 6.

Placement: env.py assertion is unit. Schema presence after upgrade is
e2e (it runs alembic / hits Postgres).

  `cubeloop_dict_to_agent_event`, …).
- `cubeplex/mcp/cubepi_runtime.py` → `cubeloop_runtime.py` (git mv) and
  every importer (`disclosure.py`, `mcp_discovery.py`, `admin_mcp.py`,

- `cubeplex/tools/**`, `cubeplex/middleware/**`
- Tests named `test_cubepi_*.py` / `test_run_manager_cubepi_*.py` —
  git mv to `test_cubeloop_*`.

Do **not** rewrite `docs/dev/**`. Do **not** rewrite SQL strings inside
historical Alembic revisions.

**Interfaces**

Public-to-CubePlex callables after the rename (same signatures, new
names):

```python

def cubeloop_dict_to_agent_event(d: dict[str, Any], timestamp: str) -> AgentEvent | None: ...
def wire_input_to_cubeloop_user_message(...) -> UserMessage: ...
def steering_message_to_cubeloop(row: SteeringMessage) -> UserMessage: ...
async def load_workspace_mcp_tools_for_cubeloop(...) -> list[AgentTool]: ...
```

Library imports: `from cubeloop import Agent, tool` and the existing
submodule paths with the root swapped (`cubeloop.providers.base`,
`cubeloop.hitl`, `cubeloop.middleware.compaction`, …). Submodule layout
did not change in 0.14.

**Core logic**

Mechanical, but not a blind repo-wide sed: skip `docs/dev`, skip SQL in
`alembic/versions/*` except the helper import lines, skip the
`eef196f4c8f9` catalog ImportError. After the rewrite, a case-sensitive
`from cubepi` / `import cubepi` grep of `backend/cubeplex`,
`backend/tests`, and `backend/alembic/env.py` is empty except that one
migration.

**Tests**

Existing unit tests keep their assertions; they just import the new
names. Update tests that `hasattr(RunManager, "_run_cubepi_path")` or
patch `cubeplex.mcp.cubepi_runtime.*`. No new behavioural tests in this
unit — behaviour is unchanged.

Run the focused unit files that import the renamed symbols
(`test_run_manager_cubeloop_dict_to_event`, `test_graph`,
`test_alembic_env`, `tests/unit/mcp/test_runtime_*`). Full agent E2E
waits until Unit 4 (SQL) is in, otherwise history/fork/delete hit

## Unit 5 — Tempo dual-read

**Files**

- `backend/cubeplex/services/tempo_client.py` — parser, TraceQL,
  search-hit summary.
- `backend/cubeplex/api/routes/v1/admin_traces.py` — tag allowlist and
  `_has_foreign_org_span`.
- `backend/cubeplex/api/schemas/trace.py` — comments only (`cubeloop.turn`).
- `backend/tests/unit/test_tempo_client.py`, `test_tempo_parser.py`
- `backend/tests/fixtures/tempo/` — keep 0.13 JSON; add a 0.14 twin.
- `backend/tests/e2e/test_admin_traces.py` — allowlist tag names.

**Interfaces**

Parser: for each vendor key, new then old.

```
cubeloop.run_id                  / cubepi.run_id
cubeloop.metadata.{org,workspace,user,conversation}_id
cubeloop.turn / cubeloop.turn.index / .stop_reason / .tool_calls.count
cubeloop.agent.tools
cubeloop.llm.raw_request / raw_response
cubeloop.tool.is_error / execution_mode
```

`gen_ai.*` is unchanged.

TraceQL org gate (and each optional filter) is an OR of the two
namespaces, still as sibling spansets so org_id on `invoke_agent` and
`gen_ai.request.model` on a chat span can match independently:

```
{ resource.service.name="cubeplex" &&
  (span.cubeloop.metadata.org_id="…" || span.cubepi.metadata.org_id="…") }
```

`select(...)` lists both spellings so 0.13 hits still populate
workspace/user/conversation/run_id on the summary.

Tag allowlist contains both `cubeloop.metadata.*` and `cubepi.metadata.*`
plus `gen_ai.request.model`. Detail defence-in-depth treats a span as
in-org if **either** org attribute matches, and as foreign if **either**
is present and differs. A span with neither org attribute is not
foreign (same as today: the summary-level `org_id is None → 404`
catches traces that have no org at all).

**Core logic**

Prefer `cubeloop.tracing.schema.attr` for dict lookups so CubePlex does
not fork the fallback. TraceQL cannot use that helper; emit both keys
explicitly.

Do not dual-write attributes. CubePlex already passes unprefixed
metadata into `tracing_context`; 0.14 prefixes it `cubeloop.metadata.*`.

**Tests** (TDD — this is the one behavioural contract)

Unit, in `tests/unit/test_tempo_parser.py` / `test_tempo_client.py`:

1. Existing 0.13 fixture still parses business ids, turn kind, raw
   request/response.
2. A 0.14 fixture (only `cubeloop.*`) parses the same view-model.
3. Search TraceQL for an org contains **both**
   `span.cubeloop.metadata.org_id` and `span.cubepi.metadata.org_id`.
4. Tag-values allowlist accepts both spellings; a random tag still 400s.
5. `_has_foreign_org_span` flags a child with the other org on either
   namespace.

E2E `test_admin_traces.py` keeps covering the HTTP 404-on-foreign-org
path; update the raw_attributes keys to also cover cubeloop.

## Risk register

1. **Autogen against a v5 DB after env.py points metadata at cubeloop.**
   Mitigation: exclude both prefixes before generating the v6 revision;
   never apply an autogen that drops `cubepi_*`.
2. **Historical revision replay.** v1–v5 SQL must keep creating
   `cubepi_*`; only the Python import of helpers moves. v6 then renames.
   `write_schema_version_op()` already writes to whichever version table
   exists.
3. **Tempo 0.14 traces invisible.** Dual-read is mandatory in the same
   PR as the pin. Parser tests cover both fixtures; TraceQL tests assert
   both keys are emitted.
4. **Downgrade that DROPs.** A copy-paste of the v4→v5 downgrade shape
   (`DROP TABLE`) would delete conversation history. v6 downgrade is a
   reverse rename.
5. **Lockfile churn.** Review `uv.lock` for unrelated bumps before
   commit.
6. **Identifier rename misses a patch string.** Tests that monkeypatch
   `cubeplex.mcp.cubepi_runtime.…` will fail loudly; grep the old module
   path after the git mv.

## Out of this plan

Matches the spec: no PyPI-instead-of-git switch, no shim dep, no frozen
docs rewrite, no JSONL directory migration, no dual-write of OTel
attrs, no new CubeLoop APIs.
