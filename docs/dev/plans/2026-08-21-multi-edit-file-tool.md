# `edit_file` 多处修改实施计划

## 范围

在现有 worktree 中完成单文件多处编辑的后端工具、提示、前端预览和测试；不实现 sandbox 原子 compare-and-write/CAS。

## 步骤

1. **契约与测试基线**
   - 确认现有 `edit_file` 参数、结果和前端事件结构。
   - 增加后端单元测试覆盖多编辑成功、同一原文匹配、重叠/失败不写入、BOM/CRLF 和结果摘要。
   - 增加前端针对多编辑 pending/result 解析和展示的行为测试；若现有组件测试基础不足，抽取纯解析 helper 测试业务契约。

2. **后端实现**
   - 将工具参数规范化为编辑列表，同时保留单编辑调用的兼容规范化路径。
   - 在原始内容上解析并校验全部编辑，拒绝重复、缺失和重叠范围。
   - 生成单次 upload 的新内容和 unified diff，保留既有 fuzzy matching 语义，并补充编辑数量、匹配模式和首个变更行。
   - 更新 `edit_file` 工具描述，明确要求模型将同一文件的多处修改合并到一次调用。

3. **前端实现**
   - 更新 `EditFilePreviewView` 的参数解析，支持 `edits[]` 和旧单编辑形状。
   - pending 状态展示所有编辑的 old/new 内容和数量。
   - 完成状态展示后端摘要并复用现有 `DiffViewer`；不修改通用事件类型，因为工具参数和结果本身是动态记录。

4. **验证与提交**
   - 运行变更相关的 backend unit tests、frontend 类型检查/组件测试和格式化检查。
   - 检查 diff、git status 和提交内容，使用 conventional commit。
   - 推送 feature branch，创建或更新 PR；PR 创建后不自动启动 Codex review loop，除非用户另行要求。

## 风险与控制

- **并发覆盖**：当前 sandbox 没有版本写入能力，本次只保证一次调用内的全量校验和单次上传；CAS 留作后续独立工作。
- **参数迁移**：内部统一成列表，但保留旧单编辑形状的规范化路径，避免历史工具调用无法重放。
- **前端事件差异**：结果字段全部按可选字段读取，未知字段不影响旧 diff 展示。
- **编辑偏移**：所有匹配先针对原始内容完成，实际替换按偏移量倒序进行，避免前序替换导致位置漂移。
