# CubePlex 0.10.0

## Features and improvements

- **Multi-provider sandbox framework and CubePod support.** Extracted a provider-agnostic sandbox framework with capability degradation (`opensandbox`, `cubepod`, `local`), added the CubePod provider (`cubepod >= 0.8.0`) with a `reset-rootfs` endpoint, and switched the Helm chart and Docker Compose deployment templates to default to `cubepod` (with `opensandbox.enabled: false` in the Helm chart).
- **Persistent sandbox lifecycle and workspace sandbox modes.** Sandboxes now preserve state across idle pauses and restarts and reclaim volumes on deletion. Workspace admins can choose between per-user and shared [sandbox modes](../guides/conversations/sandboxes.md).
- **Standalone `wait_for_tasks` tool.** Added a dedicated `wait_for_tasks` tool with single-call, fail-closed semantics for coordinating background sandbox commands.
- **Feishu/Lark QR-code onboarding and group topics.** Added one-click QR-code bot onboarding in the [Feishu/Lark guide](../guides/im/feishu.md), isolated Feishu group topics into per-thread conversations, and included quoted parent message context.
- **IM control and model commands.** Added `/steer`, `/stop`, `/models`, `/model`, and `/help` commands across [IM connectors](../guides/im/overview.md), and allowed `persona_update` during IM runs.
- **Model catalog and runtime updates.** Added OpenRouter reasoning capability and Baidu ERNIE model support, refreshed the `models.dev` catalog snapshot, and upgraded CubeLoop to `0.16.2`.

## Fixes

- **HITL responder gating and run finalization.** Restricted web and IM human-in-the-loop responses to the active turn actor or bound responder, fixed errored-pause cancel deadlocks and chained-pause finalization races, and hid non-actor hints until auth state hydrates.
- **IM queue ordering and background notices.** Preserved per-conversation FIFO ordering, deferred busy queue items, cancelled pending HITL prompts when new messages arrive, delivered idle background task notices to IM channels, and rendered post-HITL replies in Discord and Teams.
- **Sandbox hydration, terminal proxy, and home directory.** Lazily hydrated image attachments when a paused sandbox wakes, bypassed the Next.js rewrite timeout for web terminal sessions, preserved image `ENV HOME` in terminals, and aligned the `cubeplex` user and browser `HOME` to `/workspace`.
- **Chat streaming, skills, and UI polish.** Hardened run stream reconciliation and mid-run steer deduplication, stopped the task progress spinner when a run is inactive, preserved skill `auto_bind` on version upgrades, contained wide Markdown table overflow, and removed the extra composer top border.

## Before upgrading

Upgrade the backend, frontend, and sandbox image together to `v0.10.0`, or install Helm chart `0.10.0`. The normal migration step adds `sandbox_mode` to `workspaces` and `available_at` to `im_run_queue`. Docker Compose `backend-migrate` and the Kubernetes upgrade job apply these changes automatically.

The Helm chart (`values.yaml`) and Docker Compose example configs now default `sandbox.provider` to `"cubepod"` (with `opensandbox.enabled: false` in Helm). If your deployment uses OpenSandbox, set `backend.sandbox.provider: "opensandbox"` (and `opensandbox.enabled: true` if using the bundled subchart) in `values.local.yaml` before upgrading.

If your organization uses OpenSandbox with a saved [sandbox policy](../admin/sandbox.md), update its default image to `ghcr.io/cubeplexai/cubeplex-sandbox:v0.10.0`. Existing running sandboxes keep their current image or runtime state until restarted after their tasks finish.
