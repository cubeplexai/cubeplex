# CubePlex 0.9.4

## 新功能与改进

- **从供应商端点发现并导入模型。** 添加供应商时，可以列出该端点实际提供的模型，包括 CLIProxyAPI、vLLM 和 Ollama。审核已声明、建议和互相冲突的字段，补齐缺失的上限，并按每批最多 100 个导入。已有模型 ID 保持不变。CLIProxyAPI 的列表可用 CubePlex 自带的 models.dev 快照补齐参数。参见[发现并导入模型](../admin/models.md#发现并导入模型)。
- **导入的模型在当前配置通过验证前保持禁用。** 验证检查流式输出、完整的工具调用，以及已声明的推理和图片输入。修改端点、密钥、上限或调用配置后，旧证据显示为待验证。已经启用的模型仍可使用。被禁用的导入模型需要当前配置通过测试后才能启用。**模型设置**只列出已启用的模型。
- **在模型上编辑调用配置。** 模型对话框显示该模型是继承供应商默认配置，还是保存了自己的覆盖。**使用供应商配置**会清除该覆盖。拥有独立覆盖的模型会显示自定义标记。
- **对话可以使用模型默认推理。** 模型默认把推理交给已保存的端点配置和模型自身的默认行为。参见[模型默认行为与可用控制](../guides/conversations/model-selection.md#模型默认行为与可用控制)。
- **长对话压缩会保留摘要。** CubeLoop 0.15.2 在消息的运行标识、时间或元数据变化后仍保留已存储的摘要。没有摘要时，压缩触发也会参考字符估算，因此长对话更少把超限历史再次发给模型。

## 修复

- **添加供应商时，自定义供应商保持靠前。** 自定义 OpenAI 兼容和自定义 Anthropic 兼容仍排在具名供应商之前。
- **名称或 slug 冲突在列出模型之前报告。** 配置步骤会先保存供应商，导入把模型加到这个已保存的供应商上。
- **实时列表只与目录不一致时采用列表值。** 导入使用列表中的值，仍可以改回目录。如果必需设置仍然缺失，提示会指出模型和字段。
- **模型对话框可以保持打开。** 未填写的供应商能力默认值不再在每次渲染时变成新对象，打开模型时对话框不再反复重置。
- **官方 DeepSeek Flash 的目录 ID 改为 `deepseek-flash`。** DeepSeek 的模型列表现在对 V4.1 Flash 返回 `deepseek-flash`。官方目录 ID 与显示名已对齐，显示名为 DeepSeek-V4.1-Flash。火山引擎目录项不变。已经保存的模型行不会被重命名。

## 升级前须知

请将后端、前端和 sandbox 镜像一起升级到 `v0.9.4`，或安装 `0.9.4` 版本的 Helm chart。常规迁移步骤会为供应商、凭证和模型增加发现与验证所需的记录，并允许对话把推理留空以使用模型默认。Docker Compose 的 `backend-migrate` 服务和 Kubernetes 升级任务会执行这些变更。本次发布不使用 0.9.0 的维护标志。

已经启用的模型保持启用，并且仍可被选择。已有测试结果但没有配置指纹的模型会显示**待验证**，直到重新测试。从未测试过的模型保持可用。已保存的价格（包括 0）不会被改写。已经指向 `deepseek/deepseek-v4-flash` 的预设继续使用该模型行。新的官方 DeepSeek 预设示例使用 `deepseek/deepseek-flash`。

如果组织保存过[沙箱策略](../admin/sandbox.md)，请将其中的默认镜像更新为 `ghcr.io/cubeplexai/cubeplex-sandbox:v0.9.4`。保存的策略优先于部署配置。正在运行的 sandbox 会继续使用原镜像，待任务结束后重启才会更换。
