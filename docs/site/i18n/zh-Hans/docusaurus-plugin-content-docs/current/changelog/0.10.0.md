# CubePlex 0.10.0

## 新功能与改进

- **多 provider 沙箱框架与 CubePod 支持。** 抽离了支持能力降级的多 provider 沙箱框架（`opensandbox`、`cubepod`、`local`），新增 CubePod provider（`cubepod >= 0.8.0`）及 `reset-rootfs` 接口，并将 Helm chart 与 Docker Compose 部署模板默认 provider 切换为 `cubepod`（Helm 中默认 `opensandbox.enabled: false`）。
- **持久化沙箱生命周期与工作区沙箱模式。** 沙箱支持在空闲暂停与重启间保留状态，并在删除时回收卷；工作区管理员可配置按用户隔离或共享的[沙箱模式](../guides/conversations/sandboxes.md)。
- **独立的 `wait_for_tasks` 工具。** 新增 `wait_for_tasks` 独立工具，以单次调用、fail-closed 语义协调后台沙箱命令。
- **飞书/Lark 扫码一键建机器人与话题线程。** 在[飞书/Lark 指南](../guides/im/feishu.md)中新增扫码一键创建机器人流程，将飞书群聊话题按线程隔离为独立对话，并注入引用父消息上下文。
- **IM 控制与模型切换命令。** 为各 [IM 连接器](../guides/im/overview.md)新增 `/steer`、`/stop`、`/models`、`/model` 和 `/help` 命令，并允许在 IM 运行中执行 `persona_update`。
- **模型目录与运行时更新。** 新增 OpenRouter 推理能力与百度文心模型支持，刷新 `models.dev` 目录快照，并将 CubeLoop 升级至 `0.16.2`。

## 修复

- **HITL 响应者校验与运行收尾。** 将 Web 与 IM 的人工确认响应限制为当前轮次发起人或绑定响应者，修复异常暂停取消死锁与链式暂停收尾竞态，并在认证状态水合前隐藏非操作者提示。
- **IM 队列顺序与后台通知。** 保障单对话 FIFO 顺序，延迟繁忙队列项并在新消息到达时取消挂起的 HITL，向 IM 频道投递空闲后台任务通知，并修复 Discord 与 Teams 在 HITL 后的回复渲染。
- **沙箱附件恢复、终端代理与家目录。** 在暂停的沙箱唤醒时按需恢复图片附件，绕过 Next.js 重写超时以稳定 Web 终端连接，在终端会话中保留镜像 `ENV HOME`，并将 `cubeplex` 用户与浏览器 `HOME` 统一到 `/workspace`。
- **流式输出、技能与界面细节。** 加固运行流状态对账与中途 steer 去重，在运行结束时停止任务进度旋转指示器，在技能升级时保留 `auto_bind` 配置，限制宽 Markdown 表格溢出，并移除输入框多余顶部边框。

## 升级前须知

请将后端、前端和 sandbox 镜像一起升级到 `v0.10.0`，或安装 `0.10.0` 版本的 Helm chart。常规迁移步骤会为 `workspaces` 表增加 `sandbox_mode` 列，为 `im_run_queue` 表增加 `available_at` 列。Docker Compose 的 `backend-migrate` 服务和 Kubernetes 升级任务会自动执行这些变更。

Helm chart（`values.yaml`）与 Docker Compose 示例配置现已将默认 `sandbox.provider` 切换为 `"cubepod"`（Helm 中默认 `opensandbox.enabled: false`）。如果当前部署使用 OpenSandbox，请在升级前于 `values.local.yaml` 中显式设置 `backend.sandbox.provider: "opensandbox"`（若使用内置 subchart 还需设置 `opensandbox.enabled: true`）。

如果组织在使用 OpenSandbox 且保存过[沙箱策略](../admin/sandbox.md)，请将默认镜像更新为 `ghcr.io/cubeplexai/cubeplex-sandbox:v0.10.0`。正在运行的 sandbox 会保持当前镜像与运行状态，待任务结束后重启才会更新。
